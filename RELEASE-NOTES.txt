AFTERHOURS 0.5 — PLAYABLE DEVELOPMENT BUILD
20 October 2026

NEW GAME SYSTEMS
Fifteen furniture types and interactive objects; twelve personal rooms;
catalog/search/blueprints; room lighting, doors, notes, playlists and events;
an expanded music sequencer, library, discs and WAV export; performances;
quests, daily gifts, XP, badges and a wallet ledger; an adoptable tabby;
three playable arcade games; an optional shared-world service.

SHARED WORLD
Real guest presence, movement/posture, seat reservations, nearby chat, shouting,
private whispers, friend requests, doorbell/host controls, music queues,
shared playback timestamps, votes and two-party furniture trading.
Dice rolls use one server result for the object, chat and avatar bubble.

UNO PLATFORM
A real Uno Platform / WinUI .NET 10 Browser WebAssembly app hosts the canvas
game through WebView2. The Release publish completed locally. A compatibility
hook normalizes DOM IDs at Uno 6.7.135's .NET 10 WebView callback boundary.
It is packaged as its own embedded script, separate from Uno's generated manifest.
The renderer is still JavaScript; this is not a complete native XAML rewrite.

VALIDATION
Game/model/database tests cover migration, ownership, purchases, duplicate
rewards, gifts, blueprints, pets, movement, seating, private chat, trades,
room doors, stage rewards, request limits and concurrent database writes.
All 33 test cases pass, including 19 movement/seating checks grouped into two
cases (50 individual checks total). The publish verifier checks the compiled
runtime, the embedded compatibility script and all 22 current game files.
Browser checks observed chat progression, song saving/playback, stage rewards,
pet adoption/training, furniture purchase/placement, room creation/lighting,
arcade completion/rewards, real two-browser chat/presence and restored identity.
The compiled Uno shell loads the playable game and its studio with no console
errors during the final startup and interaction check.

REMAINING
The roadmap lists incomplete systems and public-release gates. This build is
playable, but it does not yet match every historical Habbo/Coke Music feature.
Accounts, operational moderation, load/security testing and a scalable shared
backend remain necessary before an unrestricted social-world launch.

PUBLIC-LAUNCH DIRECTION
Visitors should be able to start as guests, then link an account to recover
the same character on another device. Durable player saves, scalable room
services, backup/restore checks, abuse controls and tested capacity are required
before promoting the live game on social media.
